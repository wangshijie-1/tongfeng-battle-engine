# 同锋 TongFeng — 基于帧缓冲的嵌入式实时双人对战平台

> 名字里有个"贪吃蛇"，但它的内核是一套不依赖任何图形库、直接驱动硬件的**嵌入式实时游戏引擎**。

[![C++17](https://img.shields.io/badge/C%2B%2B-17-blue)]() [![Platform](https://img.shields.io/badge/platform-aarch64%20%2F%20Linux-lightgrey)]() [![Build](https://img.shields.io/badge/build-CMake-orange)]()

## 这不是一个"玩具贪吃蛇"

本项目运行在 ARM (aarch64) 嵌入式 Linux 开发板上，**没有 SDL、没有图形库、没有字体库**——从像素、字体、键盘事件到多线程调度，全部从 Linux 底层接口之上手工构建：

| 层次 | 常见做法 | 本项目做法 |
|---|---|---|
| 显示 | SDL2 / ncurses | 直接 `mmap` 帧缓冲设备 `/dev/fb0`，手写画点/画矩形/越界裁剪 |
| 文字 | 系统字体 | 自研 **8×8 ASCII + 16×16 中文点阵字体引擎**，UTF-8 双轨解析，Python 脚本从 TTF 提取字模 |
| 输入 | 终端读字符 | 双通道：终端 ANSI 转义序列解析 + **evdev 驱动级事件**（自动检索键盘设备、支持热插拔） |
| 并发 | 单线程 | 双蛇双线程独立节拍移动 + 渲染监视线程，`mutex` + `atomic` 保证线程安全 |
| 画面恢复 | 全屏重绘 | **像素级缓存还原**：暂停遮罩/提示文字覆盖前缓存原始像素，退出时无损还原 |

## 系统架构

```
┌────────────────────────── GameEngine (状态机调度) ──────────────────────────┐
│   MENU ── SINGLE_PLAYER ── TWO_PLAYER ── PAUSED ── GAME_OVER                │
│        统一输入轮询 → 按状态分发处理器 → 节拍驱动 update/render               │
├─────────────── modes/ ───────────┬────────────── core/ ────────────────────┤
│  SingleMode   双缓冲增量渲染      │  Screen    /dev/fb0 mmap 单例(线程安全) │
│  TwoPlayerMode  双蛇双线程        │  KeyInput  evdev + ANSI 双通道输入      │
│  MenuMode     菜单/配置面板       │  Font      自研点阵字体引擎(UTF-8)      │
│                存档/继续游戏       │  Render    增量渲染(脏矩形思想)         │
│                                 │  Snake/Board/Food  纯逻辑，零渲染依赖    │
└──────────────────────────────────┴──────────────────────────────────────────┘
```

## 核心技术点

### 1. 帧缓冲直写渲染（无图形库）
- `mmap` 映射 `/dev/fb0`，以像素为单位直接操作显存；
- 画矩形算法内置**越界裁剪**：杜绝像素索引换行导致的"食物卡在两格中间"错位 bug——这是一个真实踩过并根治的渲染缺陷；
- 所有布局依据 `ioctl` 读取的真实分辨率计算，禁止硬编码，天然适配不同尺寸的屏幕。

### 2. 自研点阵字体引擎
- 8×8 英文/数字 + 16×16 中文两套点阵，UTF-8 流式解析（单字节走 ASCII 表，`0xE0` 引导的三字节走中文码表）；
- 字模由 Python 脚本从 TTF 字体自动提取生成，支持整数倍缩放与居中布局。

### 3. evdev 驱动级输入（支持热插拔）
- 扫描 `/dev/input/event*`，按设备能力位自动识别键盘，event 编号变化时自动重连；
- 同时保留终端 ANSI 转义序列解析通道，开发期在 PC 上调试、部署期在开发板上运行，一套代码两用。

### 4. 双人模式：真正的多线程实时对战
- 两条蛇各占一个独立线程，按各自速度独立累计时间移动（速度不同 → 节拍间隔不同）；
- 渲染线程以 10ms 固定帧率只"监视"变化并增量绘制，逻辑与渲染彻底解耦；
- `std::mutex` 保护共享棋盘/蛇身，`std::atomic` 管理死亡/胜负/暂停标志；
- 死亡判定只在"某条蛇真正移动之后"进行，避免预测头误判；
- 暂停采用**冻结不退出**策略：线程不销毁，恢复时无缝续跑，无残留旧帧。

### 5. 画面无损还原
- 暂停遮罩、开局提示文字绘制前，先缓存其覆盖区域的原始像素（`PausePixelCache`）；
- 退出时整块写回显存，零重绘、零闪烁、零残留。

### 6. 游戏性设计
- 体力/加速系统：加速每格 −1 体力、正常每格 +1，耗尽强制解除并锁定，恢复至阈值后解锁；
- 存档系统：完整序列化蛇身/方向/速度/体力，切菜单自动保存，读档原地复活；
- 全局配置面板：格子尺寸/起步速度/加速速度三档可调，改动经确认弹窗生效（并清档防不一致）。

## 构建

交叉编译（aarch64，默认 CMake 工具链已内置）：

```bash
mkdir build && cd build
cmake ..
make        # 产物输出至 bin/GreedySnake
```

在开发板上运行（需帧缓冲设备权限）：

```bash
./bin/GreedySnake
```

## 目录结构

```
.
├── GameEngine.cpp/.h   # 引擎：状态机、输入分发、节拍、存档、暂停缓存
├── main.cpp            # 入口
├── core/               # 底层设施：Screen/KeyInput/Font/Render/Snake/Board/Food
├── modes/              # 游戏模式：SingleMode/TwoPlayerMode/MenuMode
├── _gen_*.py           # 字模/素材生成脚本（Python 从 TTF 提取点阵）
└── CMakeLists.txt      # aarch64 交叉编译配置
```
